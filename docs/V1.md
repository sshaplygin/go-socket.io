# V1 usage

Use `socketio` for the server and `client` for the Go client. Both speak
Socket.IO protocol v4 over Engine.IO protocol v3. See the
[runnable examples](../_examples/README.md).

## Connections and namespaces

`server.Of("/chat")` registers a namespace; `cl.Socket("/chat")` selects one
on a `*client.Client`. A server callback receives `socketio.Conn`; a client callback
receives `client.Conn`. They represent different roles and are not interchangeable.
The server owns rooms, broadcast selection, connection middleware and handshake
request metadata. A client sends events to the server and receives its replies.

The dynamic child namespaces of `Server.OfFunc` are never removed (see its
documentation). Use restrictive match functions and authenticate at the root
namespace `/`: a rejected root connection cannot create children.

A trailing callback passed to `Emit` requests an acknowledgement. Handler return
values produce an ACK only when the peer requested one. A final `AckFunc` parameter
lets the handler acknowledge later; in that case its return values are ignored.
`OnEvent` replaces a handler; `On` appends listeners, `Once` adds a one-shot listener,
and `Off` removes listeners for the event. When an untyped handler's argument
types do not match an incoming event, the decode error goes to `OnError` and the
handler does not run. This holds for server and client handlers alike. If the peer
requested an acknowledgement, for example a server `Emit` with a callback to a Go
client, it receives the same error ACK as from an acknowledged typed descriptor
([protocol rules](PROTOCOL.md#socketio-protocol-v4),
[typed events](#typed-events)); otherwise nothing is sent. A Go callback whose
parameters cannot decode that error object reports a decode error instead of
being called, like any other ACK it cannot decode. An event without listeners gets
no ACK. Its arguments are decoded only for the socket's event middleware
(`Namespace.Use`); without middleware they are discarded undecoded, so a value
that cannot be decoded, such as `1e400`, does not reach `OnError`.

`Emit` encodes arguments synchronously and may call application marshalers.
Queue admission does not wait for free capacity; transport writes run in the
background. A full connected write queue closes the connection with
`ErrWriteBufferFull`.

Lifecycle event names never reach the wire. A server `Conn.Emit` of `connect`,
`disconnect`, `disconnecting` or `error`, also through `Volatile` or `Compress`,
calls the socket's own listeners of that name, and the server discards incoming
events with these names. The Go client keeps local the names that
`socket.io-client` 2.x and 1.x keep local, and `disconnecting`: `connect`,
`connect_error`, `connect_timeout`, `connecting`, `disconnect`, `disconnecting`,
`error`, `reconnect`, `reconnect_attempt`, `reconnect_error`, `reconnect_failed`,
`reconnecting`, `ping` and `pong`. Its `Emit` of one of them, with any flags,
calls the namespace's listeners of that name with the `Conn` and the arguments, a
trailing callback included, and requests no acknowledgement. A `Socket` or
`Client` without a connected namespace neither calls listeners nor buffers the
event. In both roles a listener error goes to `OnError`, and a lifecycle `Emit`
from such a listener does nothing. Typed sends of these names return
`ErrInvalidEventName`. A socket.io 2.5.0 server without an `error` listener on
the socket exits on an incoming `error` event, and an incoming `disconnect` or
`disconnecting` event runs the listeners of that name on a socket that stays
connected.

Incoming event handlers run on the connection's dispatcher. Application-initiated
disconnects can run lifecycle callbacks concurrently. Synchronize shared mutable
state, including values stored with `SetContext`.

`Conn.Disconnect` closes one namespace; `Conn.Close` closes the underlying
connection and its namespaces. A client's `Socket.Close` closes that namespace;
closing the last active socket also closes its Engine.IO connection.

A namespace connection generation is one join of a namespace, from its CONNECT to
its disconnect; a reconnection starts a new generation with a new `Conn`.
A `client.Conn` belongs to one generation. After that
namespace disconnects, its sends are dropped and its `Close`/`Disconnect` calls
do nothing. Retain `cl.Socket("/chat")` to buffer events during recovery and send
through the reconnected namespace. A retained server `Conn` likewise cannot
directly send to or change the rooms of a replacement namespace socket with the
same ID; its `Rooms` returns nil after room cleanup.

`Conn.EngineConn()` exposes Engine.IO metadata such as `ID`, `Transport`,
`Upgraded`, `ReadyState` and `RemoteAddr`, and `Close`. Socket.IO owns the
connection's frame I/O: application calls to `NextReader`, `NextWriter` or
`NextWriterCompress` interfere with the library and corrupt the packet stream.
Use Socket.IO events for application messages.

`OnError` receives a nil `Conn` for root connection-middleware and `OnConnect`
failures. Errors for other unjoined namespaces receive an inactive connection:
`Connected` is false, sends are dropped, and room operations have no effect.
Check for nil before using the connection. Panics in `OnError` are recovered and
logged at WARN.

The end of an Engine.IO session is not an error, whatever ends it: a client or
server close, a dropped connection, a transport failure while reading or writing, a ping timeout,
`Server.Close`, `EngineConn().Close()` or a message past the size limit (see the
[server limit](PROTOCOL.md#engineio-protocol-v3) and [client limits](#client-limits)). `OnDisconnect`
receives the reason, and neither the server's nor the Go client's `OnError` is
called, as socket.io 2.5.0 emits no `error` event for a disconnect. `OnError` still
receives errors of a packet that was read in full (its header, arguments,
attachments or ACK), encoding errors of an outgoing packet raised before it reaches
the transport, `ErrWriteBufferFull`, middleware and `OnConnect` errors, and errors
for a namespace that has already disconnected.

## Cross-origin access

The default accepts every origin, including credentialed browser requests.
Cookie-authenticated applications should configure explicit origin checks.
`engineio.WithCORS(false)` disables polling CORS headers and restores same-origin
websocket checks; it does not reject cross-origin polling requests. See the
[protocol CORS rules](PROTOCOL.md#cors) for an allow-list that still admits
non-browser clients, which send no Origin, and for preflight behavior.

## Rooms and broadcasting

Rooms belong to one namespace: a socket of `/chat` that joins `r` is not in room
`r` of `/`. A socket joins the room named by its ID when it connects. `Conn.Rooms`
lists the ID room with the others.

When a connecting socket joins its ID room and receives broadcasts is stated with
the connection middleware under [choosing a server API](#choosing-a-server-api).

The socket.io 2.x calls map to these methods:

| socket.io 2.x server | This library |
| --- | --- |
| `socket.join(room)`, `socket.leave(room)`, `socket.leaveAll()` | `c.Join(rooms...)`, `c.Leave(room)`, `c.LeaveAll()` |
| `Object.keys(socket.rooms)` | `c.Rooms()` |
| `io.emit(event, ...)`, `io.of(nsp).emit(event, ...)` | `server.Of("/").Emit(event, ...)`, `server.Of(nsp).Emit(event, ...)` |
| `io.to(room).emit(...)`, `io.in(room).emit(...)`, `io.to(a).to(b).emit(...)` | `server.Of(nsp).To(room).Emit(...)`; `To(a, b)` or `To(a).To(b)` for a union |
| `io.to(socketID).emit(...)` | `server.Of(nsp).To(socketID).Emit(...)` |
| `socket.broadcast.emit(...)` | `c.Broadcast().Emit(...)`: the namespace except `c` |
| `socket.to(room).emit(...)` | `c.To(room).Emit(...)`: the room except `c` |
| `io.volatile`, `socket.volatile`, `socket.compress(false)` | `Volatile()` and `Compress(false)` of a `ServerNamespace`, an `Emitter` or a `Conn` |
| `io.local` | `Local()` of a `ServerNamespace` or an `Emitter` |
| `io.of(nsp).clients(fn)`, `io.of(nsp).in(room).clients(fn)` | `server.Of(nsp).SocketIDs()`, `SocketIDs(room)` |
| `io.of(nsp).connected`, `io.of(nsp).connected[id]` | `server.Of(nsp).Sockets()`, `Socket(id)` |
| `io.of(nsp).adapter.rooms` | `server.Rooms(nsp)`, `server.RoomLen(nsp, room)` |
| `socket.on('disconnecting', fn)` | `server.Of(nsp).OnEvent("disconnecting", func(c socketio.Conn, reason string) {...})` |
| `io.of(nsp).adapter.remoteJoin(id, room, fn)` and the other `socket.io-redis` requests | the `redis.Cluster` methods under [adapters and Redis](#adapters-and-redis) |

A server does not send a broadcast of a lifecycle name, `connect`, `disconnect`,
`disconnecting` or `error`, to its sockets. Listeners that the server registered
for that name can run for the selected sockets instead, as with `Conn.Emit`
([lifecycle names](#connections-and-namespaces)). The
[protocol notes](PROTOCOL.md#socketio-protocol-v4) compare lifecycle-name
broadcasts with socket.io 2.5.0.

## Choosing a server API

Use `Server.Of(namespace)` and its `ServerNamespace`/`Emitter` methods for new
code. An emitter selects a namespace or room union, exclusions and delivery flags,
and its `Emit` returns adapter errors. The `Server.*(namespace, ...)` methods
remain wrappers in the upstream v1.7.0 call shape. Code from v1.4.2 must add the
namespace argument: `BroadcastToRoom(room, event, stringValue)` still compiles
but is interpreted as `(namespace, room, event)` and can deliver elsewhere or
nothing at all.

ACK behavior depends on the target. A direct `Conn.Emit` or single-socket emitter
accepts a trailing callback. A broadcast through `ServerNamespace` or `Emitter`
rejects it with `ErrBroadcastAck`. The retained `BroadcastToRoom` and
`BroadcastToNamespace` wrappers register callbacks per socket with the memory
adapter, while Redis rejects broadcast callbacks. Their boolean result does not
report delivery (see their documentation). Prefer an emitter when the caller needs
the error.

`ServerNamespace.Use` (or `Server.Use`) registers namespace connection middleware
before `OnConnect`. A connected `Conn` also exposes `Namespace.Use`, which checks
incoming events on that socket. These are separate stages: connection middleware
accepts or rejects a namespace join; event middleware accepts or rejects a message.
A socket that passed the middleware is already in its ID room and the namespace
while `OnConnect` runs, so broadcasts from `OnConnect`, such as a presence update to
the namespace, reach it after its CONNECT. A socket that `OnConnect` rejects never
receives them and gets no `OnDisconnect`; see `Server.OnConnect`.

## Constructor configuration

`socketio.NewServer()`, `engineio.NewServer()` and `client.New(addr)` work without
options. Each role has its own `Option` functions. Options apply in order; the last
setting wins. The constructors copy client headers and query values and the engine's
cookie and built-in transport settings, so later changes to the values passed in do
not affect the instance.

The Engine.IO heartbeat (PingInterval and PingTimeout) and the Socket.IO
`WithCloseTimeout` are independent. Nonpositive `WithCloseTimeout` values select one
minute. Nonpositive `WithWriteBufferSize` values select 1024
packets for the server and 64 for the Go client. The bound counts packets, not bytes:
a connection whose client reads slowly can hold up to that many queued packets of
whatever size the application emits, so the server's worst case per connection is
1024 queued application packets plus the one being written, and lifecycle CONNECT
and DISCONNECT packets, which have their own allowance of up to twice the bound. The
queue does not reserve memory for its bound in advance. Each option's godoc describes
its defaults and bounds.
`socketio.WithLogger` configures Socket.IO and its engine. A later
`WithEngineOptions(engineio.WithLogger(other))` overrides only the engine's sink.

```go
server := socketio.NewServer(
    socketio.WithEngineOptions(
        engineio.WithPingInterval(25*time.Second),
        engineio.WithPingTimeout(20*time.Second),
    ),
    socketio.WithWriteBufferSize(1024),
    socketio.WithCloseTimeout(time.Minute),
)
server.Of("/").OnConnect(func(c socketio.Conn) error {
    c.Join("lobby")
    return nil
})

cl, err := client.New("http://127.0.0.1:8000",
    client.WithWriteBufferSize(64),
    client.WithCloseTimeout(time.Minute),
)
if err != nil {
    return err
}
cl.OnConnect(func(c client.Conn) error { return nil })
```

## Disconnect reasons

`OnDisconnect` receives these reason strings. `transport close`,
`transport error`, `ping timeout` and `forced close` equal the constants
`ReasonTransportClose`, `ReasonTransportError`, `ReasonPingTimeout` and
`ReasonForcedClose` of package `engineio` and of package `engineio/client`. Each
package has its own `CloseReason` string type, so compare with a conversion, such as
`string(engineio.ReasonPingTimeout)`. The other four reasons have no exported
constants. `Server.Close` reports `forced close`, not the value of
`engineio.ReasonServerShutdown`.

| Reason | Server `OnDisconnect` | Go client `OnDisconnect` |
| --- | --- | --- |
| `client namespace disconnect` | The client sent DISCONNECT for the namespace | Not used |
| `server namespace disconnect` | `Conn.Disconnect` or `Conn.Close` | Not used |
| `io client disconnect` | Not used | `Socket.Close`, `Conn.Disconnect`, `Conn.Close` or `Client.Close` |
| `io server disconnect` | Not used | The server sent DISCONNECT for the namespace |
| `transport close` | The client's Engine.IO `CLOSE` packet, or its orderly websocket close frame | The server's `CLOSE` packet, or its websocket close frame with code 1000, 1001 or none |
| `transport error` | Other transport failures, such as a websocket dropped without a close frame, a pending poll that the client aborts or a message past the [server limit](PROTOCOL.md#engineio-protocol-v3) | Other transport failures, such as a message past the [client limit](#client-limits) |
| `ping timeout` | No packet from the client within PingInterval + PingTimeout, or another deadline that ends a transport read or write: an `http.Server` `ReadTimeout` on an HTTP/1.x request body or `WriteTimeout` on an HTTP/1.x response being written, a poll request's context deadline (for example under `http.TimeoutHandler`), or a TCP timeout | No `PONG` from the server within PingInterval + PingTimeout |
| `forced close` | Other server-side closes, such as `Server.Close`, `EngineConn().Close()` or a full write queue | Other client-side closes, such as a full write queue |

[PROTOCOL.md](PROTOCOL.md#engineio-protocol-v3) lists the websocket close codes.
An `http.Server` `WriteTimeout` shorter than a pending poll is described under
[deployment](#deployment).

## Sessions and shutdown

`engineio.Conn.Close` is orderly; `engineio.Abort` is immediate. A session leaves
the server's registry, and `Count`, when its close finishes, however it ends;
`Server.Remove` (of `socketio.Server` or `engineio.Server`) unregisters a session
earlier and does not close its transport.
An `IDGenerator` may then issue the ended session's ID again. A Socket.IO connection
whose ID belonged to a connection that is still running its `disconnecting` or
`OnDisconnect` handlers connects after those handlers return, so the two never share
sockets or rooms. Register handlers and middleware before the server accepts
connections, and retain request metadata in `engineio.WithConnInitor` when needed.

`Server.Close` closes every session, waits a bounded time for the `OnDisconnect`
handlers and for the adapters that own resources, which implement `io.Closer`, and
joins their close errors with the engine's. Its documentation states the bound, the
timeout error, a repeated call and why a callback of the same server, such as an
admin `shutdown` event handler, must call it on its own goroutine.

## Deployment

With the polling transport enabled, as by default, leave `http.Server.WriteTimeout`
unset or longer than PingInterval + PingTimeout (45 s with the defaults). A pending
poll waits on the server for the session's next packet. Over HTTP/1.x, a packet
written after the poll has waited longer than `WriteTimeout` does not reach the
client, and the session does not see the loss of a small response
([polling request I/O](PROTOCOL.md#engineio-protocol-v3)).

Over HTTP/1.x with a `WriteTimeout` shorter than PingInterval, an idle
`socket.io-client` 1.7.4 or 2.5.0 that stays on polling reports `transport error` at
its next heartbeat and reconnects, and the server reports `transport close`. The
same clients on websocket, or upgraded to it, stay connected.

Engine.IO sessions live in the server instance that opened them: a polling request
whose `sid` belongs to another instance is answered HTTP 400 with code 1
`Session ID unknown`. Behind a load balancer, route every request of a session to
the instance that opened it (session affinity).

The server limits neither the number of concurrent sessions nor the handshake rate.
A handshake that is never followed by another request
holds its session for PingInterval + PingTimeout (45 s with the defaults). Measured
with the default server on darwin/arm64 and Go 1.25, 5,000 such polling handshakes
held 4 goroutines and 14 KiB of heap per session. Limit the connection and request
rate of untrusted clients in front of the server, at a reverse proxy or in HTTP
middleware, or reject handshakes with `engineio.WithRequestChecker`, and authenticate
in connection middleware.

## Adapters and Redis

`redisadapter.New()` returns a factory without connecting to Redis.
Namespace registration applies the factory once and retains construction errors.
It connects to Redis synchronously and can block up to `WithSubscribeTimeout`
(ten seconds by default), including subscription acknowledgements. The Redis factory
constructs one namespace at a time, so a queued registration can wait longer.
`Server.Serve` checks for these errors when it starts. Later namespace failures do
not stop a running `Serve`: that namespace rejects connections and its emitter
returns the factory error. Register required namespaces before starting `Serve`
to detect their construction failures at startup.
`SetAdapter` affects future namespaces; existing ones keep their adapter. Nil selects
memory. Constructor options are ordered, with the last `WithAdapter` winning.
[Shutdown](#sessions-and-shutdown) closes adapters that implement `io.Closer`.

Adapters may implement `adapter.SocketLookupBinder` to receive the server's live
socket lookup independently of room membership. `Send` and `SendAll` wrap `SendTo`
and return no error, so an adapter logs their `SendTo` failures instead of dropping
them, as the Redis adapter does at WARN, or at DEBUG once closed. `Rooms(nil)` is
equivalent to `AllRooms`. The `Adapter` method set is fixed for v1; further
capabilities use optional interfaces.

```go
import (
    socketio "github.com/sshaplygin/go-socket.io"
    "github.com/sshaplygin/go-socket.io/adapter"
    redisadapter "github.com/sshaplygin/go-socket.io/adapter/redis"
)

server := socketio.NewServer(socketio.WithAdapter(redisadapter.New(
    redisadapter.WithAddr("127.0.0.1:6379"),
    redisadapter.WithPrefix("socket.io"),
)))
server.Of("/").OnConnect(func(c socketio.Conn) error { c.Join("lobby"); return nil })
server.ForEach("/", "lobby", func(c adapter.Socket) { c.Emit("news", "hello") })
```

External adapters take `adapter.Socket`, whose methods are `ID`, `Emit` and
`EmitWithOptions`. The last method applies only `Volatile` and `NoCompress` to that
socket; the adapter owns room/exclusion/cluster selection. The server's
`socketio.Conn` implements this contract. `ForEach` callbacks needing server-specific metadata can use a checked type assertion
to `socketio.Conn`. `adapter.Memory` releases its index lock before invoking sockets or
callbacks. Redis composes Memory and uses the Node-compatible wire described in
[the protocol notes](PROTOCOL.md#redis-cluster-interoperability).

`SendTo` supports exclusion and room-union deduplication across instances,
transmits volatile/compression flags, and returns encoding/publication failures.
Broadcast `PUBLISH` is bounded by `WithRequestsTimeout` (five seconds by default)
for each I/O phase (dial, write, read), so a stalled publication can take two to
three times that before `SendTo` returns the timeout error. Local delivery and
publication are not transactional: local delivery is not rolled back, and a timeout
does not mean remote instances missed the broadcast, so retrying may duplicate it.
A broadcast with a trailing callback is rejected before any delivery.
`BroadcastToRoom` and `BroadcastToNamespace` return no error: these rejections and
publication failures are logged at WARN, or at DEBUG once the adapter is closed,
one record per failed call; no rate limiting.

All namespaces of a factory share one subscriber connection. The adapter detects
its loss when the connection reports an error: Redis closes or resets it, or, on a
silent network partition, TCP keepalive gives up, which can take tens of minutes
because the idle subscriber has no read deadline. It then logs
`socketio: redis subscription lost` at WARN with the error, logs each failed
reconnect attempt as `socketio: redis resubscribe failed` at DEBUG, and logs
`socketio: redis subscription restored` at INFO once it is subscribed again: one
WARN and one INFO record per outage, however long. Reconnect attempts follow a
backoff that doubles from 100 milliseconds to 5 seconds: the first attempt comes
100 milliseconds after the loss, then 0.3, 0.7, 1.5, 3.1 and 6.3 seconds after it,
then every 5 seconds. These times hold while Redis refuses connections; an
attempt that gets no answer, as on a silent partition, adds its own duration, at
most `WithSubscribeTimeout`, before the next delay begins. The backoff starts over
at 100 milliseconds only when the lost subscription had stayed up for at least 5
seconds; a subscription that fails sooner after its recovery continues the backoff
where it stopped, also when namespaces were registered or closed in between.
`Close` of the last namespace of a factory ends the subscription and the reconnect
attempts, and is not itself logged as a loss. A namespace `Close` that cannot
unsubscribe within `WithSubscribeTimeout`, because the write fails or Redis does
not acknowledge it, closes the shared subscriber; the remaining namespaces log
that as a loss and reconnect.

While its subscription is down, an instance receives no broadcasts, cluster
requests or responses from other instances. Redis Pub/Sub does not keep messages
for a missing subscriber, and nothing replays them after recovery. While Redis is
unreachable, `SendTo` returns the connection error. A publisher is not told about
a peer's gap: its `SendTo` returns nil once Redis accepts the `PUBLISH`, also while
a peer has not resubscribed yet, so broadcasts published in that gap are lost for
that peer. A peer resubscribes at its next backoff attempt after Redis returns:
for an outage that starts the backoff over, that is at most about the outage's
length plus 100 milliseconds later, and never more than about 5 seconds later, plus
the duration of an attempt that was already waiting for an answer. Cluster
requests of the disconnected instance wait for its subscription within
`WithRequestsTimeout`; its peers count only subscribed instances.

For errors and cancellation, assert the adapter to `redis.Cluster` and use its
context-aware methods. `IDsContext`, `AllRoomsContext` and `LenContext` query the
cluster; `ClientRooms`, `RemoteJoin`, `RemoteLeave` and `RemoteDisconnect` control
remote sockets. `CustomRequest` exchanges JSON with the handler set by
`WithCustomRequestHandler`. `WithRequestsTimeout` defaults to five seconds; caller
deadlines may shorten it. Query timeouts return validated partial results with
`redis.ErrRequestTimeout`; caller cancellation returns the context error, and
adapter closure returns `redis.ErrAdapterClosed`. IDs/AllRooms return partial
results and Len returns -1 on failure; IDs, AllRooms, Len and Clear log their errors
at WARN, or at DEBUG once the adapter is closed. `ClearContext` removes a snapshot
of room members under one deadline, without rolling back completed removals.

The factory invokes its custom handler once per namespace request. Requests from
other instances for custom handlers and for one socket (its rooms, remote join,
leave and disconnect) run outside the
subscriber's reader, at most 32 at a time per factory, each bounded by
`WithRequestsTimeout`; a request that arrives while 32 are running is dropped and
logged at WARN as `socketio: redis remote request worker limit reached`. A dropped
request or a handler error makes Node callers time out because that wire has no
error-response field. Handlers must honor cancellation.
Server-created adapters receive an independent socket lookup, so LeaveAll does not
hide a live socket from remote commands. Standalone adapter users can optionally
bind their own lookup through `adapter.SocketLookupBinder`; a remote join, leave or
disconnect reaches such a socket only through the method it implements:
`Join(...string)`, `Leave(string)`, `Disconnect()`, or `Close() error` for a
disconnect that closes the connection.

## Client limits

`client.WithMaxMessageSize(bytes)` configures received messages; the last option wins.
The low-level equivalent is `engineio/client.Dialer.MaxMessageSize`. Zero and negative
values select the 1 MiB default. See [protocol limits](PROTOCOL.md#engineio-protocol-v3)
for the transport boundaries. Custom transports can implement `SetReadLimit(int64)`;
otherwise their implementation must enforce the limit itself. Set an explicit
larger limit before connecting if the application receives larger messages.
A message past the limit ends the session: `OnDisconnect` receives `transport error`
and `OnError` is not called. For the built-in transports the Engine.IO client logs
`engineio: message too large` at WARN, with `transport` and an `err` that states the
limit, through the fallback logger described in the [`logger` package
documentation](../logger/logger.go), not through `client.WithLogger`. A custom
transport that enforces the limit itself must report it.

`polling.Default` reads `http.DefaultTransport` once, when the polling package
initializes. When it is a `*http.Transport`, the default polling HTTP client owns a
clone with up to 64 idle connections per host, shared by every client that dials
through `polling.Default`; otherwise that RoundTripper is used as it is. Later
replacement or changes of `http.DefaultTransport` do not affect it. Idle
connections stay in the pool for the transport's idle timeout after clients close;
`polling.Default.Client.CloseIdleConnections()` releases them. To choose
connection-pool or HTTP limits, supply an application-owned HTTP client with
`client.WithTransports(&polling.Transport{Client: httpClient})`; when upgrades are
wanted, add a websocket transport with a handshake timeout, such as
`&websocket.Transport{HandshakeTimeout: 20 * time.Second}`, because
`websocket.Default` has none. Reuse that HTTP client across related Socket.IO
clients and close its idle connections when the application no longer needs the
pool.

## Differences from the socket.io 2.x JavaScript API

The wire protocol and its differences from the reference server are described in
[PROTOCOL.md](PROTOCOL.md). These parts of the socket.io 2.x JavaScript API have no
counterpart, or a different one, in this library:

- Server
  - The client bundle is not served (`serveClient`): `GET /socket.io/socket.io.js`
    is answered HTTP 400 `{"code":0,"message":"Transport unknown"}`. Serve
    `socket.io-client` from a CDN, a bundler or a file handler of the application.
  - Event middleware (`Conn.Use`) cannot rewrite an event: replacing an element of
    its argument slice does not change what the handler receives, where
    `socket.use` can change the packet.
  - `Handshake().Address` includes the port of the remote address; the reference's
    `handshake.address` does not. There is no separate `issued` field: `Time` is the
    socket's creation time.
  - There is no `binary(false)` flag.
  - The lifecycle names behave differently in broadcasts (see
    [rooms and broadcasting](#rooms-and-broadcasting)). `newListener`,
    `removeListener` and `connection`, which the reference keeps local in some of
    its emits, are sent as ordinary events by `Conn.Emit` and a namespace `Emit`.
- Go client
  - There is no `connect_error`, `connect_timeout`, `connecting` or `reconnecting`
    callback; the client's callbacks are `OnReconnectAttempt`, `OnReconnect`,
    `OnReconnectError`, `OnReconnectFailed`, `OnPing` and `OnPong`.
  - There are no `forceNew` and `multiplex` options.
  - There is no `initialPacket` option and no accessor for the Engine.IO connection
    or its transport, which the server has as `Conn.EngineConn()`.
  - `Volatile` and `Compress` exist on `client.Conn`, not on `*client.Socket`.

## Typed events

Package `socketio` provides `NewEvent[T]` and `NewAckEvent[T, R]`. Declare a
single descriptor and use it with both the server and the independent Go client:

```go
type Notice struct {
    ID int64
    Content string
    File parser.Buffer
}

notice := socketio.NewEvent[Notice]("notice")
if err := notice.Handle(server.Of("/chat"),
    func(ctx context.Context, conn socketio.Conn, value Notice) error {
        // ctx lasts until this namespace generation ends.
        return nil
    }); err != nil {
    return err
}
if err := notice.HandleClient(cl.Socket("/chat"),
    func(ctx context.Context, peer socketio.Endpoint, value Notice) error {
        return nil
    }); err != nil {
    return err
}
if err := notice.EmitTo(ctx, server.Of("/chat").To("room"), value); err != nil {
    return err
}
```

The snippet uses imports `context`, `github.com/sshaplygin/go-socket.io` as
`socketio` and `github.com/sshaplygin/go-socket.io/parser`. `server`, `cl`, `ctx`
and `value` are application-owned instances. `HandleClient`
accepts either a `*client.Client` for its selected namespace or a `*client.Socket`.
Its endpoint is the actual client connection of that namespace generation.
Typed client programs import package `socketio` for descriptors; the `client`
package itself does not import it. The exported
`RegisterEvent`, `SendEvent` and `RequestAck` methods of `client.Client` and
`client.Socket` are bridges for `socketio.Event` and `socketio.AckEvent`, not
application extension points.

`T` is exactly one positional argument, even when it is a slice or struct. Nested
`parser.Buffer` fields use binary attachments. Declared integer types retain their
full precision in Go-to-Go traffic. A JavaScript application remains subject to
JavaScript's numeric precision.

For a result, register and send with an acknowledged descriptor (also importing
`fmt` and `time`):

```go
lookup := socketio.NewAckEvent[int64, Notice]("lookup")
if err := lookup.Handle(server.Of("/chat"),
    func(ctx context.Context, conn socketio.Conn, id int64) (Notice, error) {
        return Notice{ID: id}, nil
    }); err != nil {
    return err
}
wait, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
result, err := lookup.EmitWithAck(wait, cl.Socket("/chat"), 42)
if err != nil {
    return err
}
fmt.Println(result.ID)
```

The ACK convention is `[null, result]` for success and
`[{"code":"...","message":"..."}]` for failure. Ordinary handler errors become
`handler_error`; recovered panics become `handler_panic`. Return
`*socketio.RemoteError` to choose a code and message, and use `errors.As` to inspect
one received from a peer. Raw or JavaScript handlers exchanging typed ACKs must
implement that envelope. Malformed responses return `ErrInvalidAck`.

A wait ends on caller cancellation/deadline, namespace disconnect
(`ErrSocketClosed`), or the internal 30-second limit (`ErrAckTimeout`). The limit
includes pre-connect buffering. Canceled buffered requests do not later flush;
admitted requests belong to one generation and are never replayed on reconnect.
A retained `*client.Socket` can buffer new requests during recovery. Typed sends on a
retained client Conn return `ErrSocketClosed` after its namespace generation ends.

Incoming handler contexts are canceled before disconnect callbacks and are
independent of application `Conn.Context()` storage and the handshake request.
Incoming event handlers share one dispatcher. Start `EmitWithAck` waits outside
a callback on that same connection, for example in a goroutine; blocking that callback
also blocks receipt of its ACK.

Typed registration rejects an existing typed or reflected listener with
`ErrDuplicateEvent`. `OnEvent` replaces the registration, and `Off`
removes either form. Empty names and the lifecycle names `connect`, `disconnect`,
`disconnecting` and `error` return
`ErrInvalidEventName`, as do typed sends of the names the Go client
[keeps local](#connections-and-namespaces). Typed sends support the built-in server connections,
clients and client namespace sockets, through the bridge methods named above.
An independently implemented endpoint with only `Emit` returns
`ErrUnsupportedEndpoint`. Successful sends mean local admission, and broadcasts
retain adapter error and partial-delivery behavior; they do not count
remote delivery or support broadcast ACKs.

## Migrating from googollee/go-socket.io

The fork's first release is **v1.5.0**. Its version sequence is independent of
upstream: it contains the upstream v1.7.0 history and replaces that implementation
under a new module path, with the API and behavior changes below. It is not a
compatible minor upgrade of upstream v1.4.2 or v1.7.0. The inherited fork tags
v0.9.1–v1.4.2 declare the upstream module path and must not be used as fork
versions. The [Go version floor](../README.md#install) is stated in the README.

Change imports from `github.com/googollee/go-socket.io` to
`github.com/sshaplygin/go-socket.io`, including subpackages. For v1.4.2 applications,
replace the separate `github.com/googollee/go-engine.io` dependency with this
module's `engineio` packages. A `replace` directive alone is not a drop-in
migration: package paths, type identities, constructors and interfaces changed.
Use server `socketio.Conn` in server callbacks and `client.Conn` for the new Go
Socket.IO client; the roles are independent.

After rewriting imports, run `go build ./... && go vet ./...`, fix what they report
and repeat until both pass. An import of a package the fork does not have, such as
upstream `engineio/session`, is reported alone: the build stops before it checks
identifiers. Once every import resolves, the build reports the renamed, removed and
re-typed identifiers in the tables below. A program that builds is not necessarily
unaffected: `socketio.NewServer(nil)` and `engineio.NewServer(nil)` still compile,
because a nil option is ignored, and run with the fork's defaults. Nothing under
[changed defaults](#changed-defaults-and-behavior) or
[calls that compile but change meaning](#calls-that-compile-but-change-meaning)
causes a compile error. For those, search the code for `NewServer(nil)`,
`BroadcastToRoom(`, `Encode(`, comparisons of `.ID()` values, `OnDisconnect` reason
strings, `DefaultIDGenerator{`, `RequestChecker`, CORS middleware in front of the
handler, `Header.Del("Origin")`, `err == io.EOF`, `Emit("error"`, `Emit("connect"`,
`Emit("disconnect` and `Rooms(`, and run the application's integration tests
against the new build.

### Calls that compile but change meaning

- Namespace socket IDs now differ: `/` uses the Engine.IO ID, while `/chat` uses
  `/chat#<engine ID>`. Use the namespace socket ID for room exclusions and remote
  adapter operations. Do not assume different namespaces share an ID.
- A v1.4.2 call `BroadcastToRoom(room, event, s)` with a string `s` is now interpreted
  as `(namespace, room, event)`. Arguments shift position and can target the wrong
  namespace or room. Supply the namespace explicitly or use
  `server.Of(namespace).To(room).Emit(event, s)`.
- With a v1.4.2-style `parser.Encoder.Encode(h, args)`, an untyped nil or nil
  `[]interface{}` now supplies a JSON `null` payload. For a namespace DISCONNECT,
  v1.4.2 wrote `1/a`; `Encode(h, nil)` now writes `1/a,null` followed by a newline.
  Use `Encode(h)` when no payload is intended: it writes `1/a,`, because the encoder
  always writes the separator after a non-root namespace, as the JavaScript
  reference encoder does. Socket.IO decoders read `1/a,` and `1/a` as the same
  packet. Non-nil argument slices remain a single JSON array; expanding them with
  `...` would instead encode only the first element.
- `Conn.Emit` or a room broadcast of
  `connect`, `disconnect`, `disconnecting` or `error`: upstream v1.7.0 sent the
  event to the client, so `c.Emit("error", msg)` reached `socket.on('error')` of
  `socket.io-client`. This library sends nothing to the client. Rename such events,
  for example to `app_error`, on both sides. See
  [lifecycle names](#connections-and-namespaces) and
  [rooms and broadcasting](#rooms-and-broadcasting).
- `engineio.Conn` readers and writers of a closed session return a wrapped
  `*engineio.CloseError` instead of a bare `io.EOF`. It unwraps to `io.EOF` only for
  a transport close. Replace `err == io.EOF` with `errors.As` for the close reason,
  or `errors.Is(err, io.EOF)` where only a transport close is meant.
- Upstream v1.7.0 ignored some `RedisAdapterOptions`: `DB` was dropped before
  dialing, so database 0 was used, and `Host`/`Port` were never applied because the
  default `Addr` is non-empty. Mapping those fields to `WithDB` or `WithAddr` can
  change the Redis database or host actually used; pass the values the old
  deployment really connected to.
- CORS middleware that sets `Access-Control-Allow-Origin` and
  `Access-Control-Allow-Credentials` and deletes the request's `Origin`, as upstream's
  `_examples/gin-cors` does, compiles but breaks cross-origin browser polling. Without
  an Origin, polling replaces the middleware's origin with `*`, which browsers refuse
  for the credentialed XHR that socket.io-client 1.x and 2.x send by default, so the
  page fails with `xhr poll error`. Remove the `Header.Del("Origin")` call and the
  middleware's CORS headers for the Socket.IO route, pass the allowed origins to the
  transports' `CheckOrigin`, and route `OPTIONS` requests for the Socket.IO path to the
  handler, which answers the preflight of a binary polling POST, as
  [`_examples/gin-cors`](../_examples/gin-cors/main.go) does; polling then reflects an
  allowed Origin with credentials and websocket refuses other origins with HTTP 403.
  Adding `engineio.WithCORS(false)` instead keeps the
  middleware's headers but, as upstream, accepts websocket connections from every
  origin, because the Origin is gone before the check. See
  [cross-origin access](#cross-origin-access).
- `engineio.DefaultIDGenerator{ID: n}` compiles but seeds nothing; IDs are random.
- `Server.Serve` returns nil after `Close`; upstream returned `io.EOF`.
- `Server.Close` called from a callback of the same server, such as an admin
  `shutdown` event handler, returned nil at once in upstream v1.7.0. The fork waits for
  the caller's own connection, which cannot finish until the callback returns, and
  returns an error wrapping `context.DeadlineExceeded` after ten seconds; code that
  treats that error as a failed shutdown reports one although the server did close.
  Call `go server.Close()` from callbacks; the `Server.Close` documentation
  describes the wait.

### Upgrading Redis clusters

Redis fleets need a separate migration step: the fork's channel names and
MessagePack broadcasts are incompatible with upstream Go peers. Give the new
fleet a distinct `redisadapter.WithPrefix`, or stop all old instances before
starting the new fleet. Read the [Redis upgrade procedure](PROTOCOL.md#upgrading-from-upstream-go-redis-adapters)
before sharing a Redis service; incompatible non-root broadcasts can stop an
upstream peer's dispatcher.
