# V1 usage

Use `socketio` for the server and `client` for the Go client. Both speak
Socket.IO protocol v4 over Engine.IO protocol v3. See the
[runnable examples](../_examples/README.md).

## Connections and namespaces

`server.Of("/chat")` registers a namespace; `cl.Socket("/chat")` selects one
on a `*client.Client`. A server callback receives `socketio.Conn`; a client callback
receives `client.Conn`. They represent different roles and are not interchangeable.
The server owns rooms, broadcast selection, connection middleware and handshake
request metadata. A client sends events to the server and receives its replies.

`Server.OfFunc` creates dynamic child namespaces that are never removed: each
child and its adapter stay registered for the server's lifetime, even if all
connections to it are rejected, so the registry grows with every distinct name a
match function accepts. Use restrictive match functions and authenticate at the
root namespace: a rejected root connection cannot create children.

A trailing callback passed to `Emit` requests an acknowledgement. Handler return
values produce an ACK only when the peer requested one. A final `AckFunc` parameter
lets the handler acknowledge later; in that case its return values are ignored.
`OnEvent` replaces a handler; `On` appends listeners, `Once` adds a one-shot listener,
and `Off` removes listeners for the event. When an untyped handler's argument
types do not match an incoming event, the decode error goes to `OnError`, the
handler does not run and no ACK is sent
([protocol rules](PROTOCOL.md#socketio-protocol-v4)); a peer waiting for that
acknowledgement needs its own timeout. Acknowledged typed descriptors reply with an
error ACK instead ([typed events](#typed-events)). An event without listeners gets
no ACK. Its arguments are decoded only for the socket's event middleware
(`Namespace.Use`); without middleware they are discarded undecoded, so a value
that cannot be decoded, such as `1e400`, does not reach `OnError`.

`Emit` encodes arguments synchronously and may call application marshalers.
Queue admission does not wait for free capacity; transport writes run in the
background. A full connected write queue closes the connection with
`ErrWriteBufferFull`.

Incoming event handlers run on the connection's dispatcher. Application-initiated
disconnects can run lifecycle callbacks concurrently. Synchronize shared mutable
state, including values stored with `SetContext`.

`Conn.Disconnect` closes one namespace; `Conn.Close` closes the underlying
connection and its namespaces. A client's `Socket.Close` closes that namespace;
closing the last active socket also closes its Engine.IO connection.

A `client.Conn` belongs to one namespace connection generation. After that
namespace disconnects, its sends are dropped and its `Close`/`Disconnect` calls
do nothing. Retain `cl.Socket("/chat")` to buffer events during recovery and send
through the reconnected namespace. A retained server `Conn` likewise cannot
directly send to or change the rooms of a replacement namespace socket with the
same ID; its `Rooms` returns nil after room cleanup.

`Conn.EngineConn()` exposes Engine.IO metadata such as `ID`, `Transport`,
`Upgraded`, `ReadyState` and `RemoteAddr`, and `Close`. Socket.IO owns the
connection's frame I/O: application calls to `NextReader`, `NextWriter` or
`NextWriterCompress` interfere with the library and corrupt the packet stream.
Use Socket.IO events for application messages.

`OnError` receives a nil `Conn` for root connection-middleware and `OnConnect`
failures. Errors for other unjoined namespaces receive an inactive connection:
`Connected` is false, sends are dropped, and room operations have no effect.
Check for nil before using the connection. Panics in `OnError` are recovered and
logged at WARN.

## Cross-origin access

The default accepts every origin, including credentialed browser requests.
Cookie-authenticated applications should configure explicit origin checks.
`engineio.WithCORS(false)` disables polling CORS headers and restores same-origin
websocket checks; it does not reject cross-origin polling requests. See the
[protocol CORS rules](PROTOCOL.md#cors) for an allow-list that still admits
non-browser clients, which send no Origin, and for preflight behavior.

## Choosing a server API

Use `Server.Of(namespace)` and its `ServerNamespace`/`Emitter` methods for new
code. An emitter selects a namespace or room union, exclusions and delivery flags,
and its `Emit` returns adapter errors. The `Server.*(namespace, ...)` methods
remain wrappers in the upstream v1.7.0 call shape. Code from v1.4.2 must add the
namespace argument: `BroadcastToRoom(room, event, stringValue)` still compiles
but is interpreted as `(namespace, room, event)` and can deliver elsewhere or
nothing at all.

ACK behavior depends on the target. A direct `Conn.Emit` or single-socket emitter
accepts a trailing callback. A broadcast through `ServerNamespace` or `Emitter`
rejects it with `ErrBroadcastAck`. The retained `BroadcastToRoom` and
`BroadcastToNamespace` wrappers register callbacks per socket with the memory
adapter, while Redis rejects broadcast callbacks. Their boolean result reports
that the namespace is registered and its adapter was constructed, even if that
adapter has since closed; it does not report delivery. Prefer an emitter when
the caller needs the error.

`ServerNamespace.Use` (or `Server.Use`) registers namespace connection middleware
before `OnConnect`. A connected `Conn` also exposes `Namespace.Use`, which checks
incoming events on that socket. These are separate stages: connection middleware
accepts or rejects a namespace join; event middleware accepts or rejects a message.

## Constructor configuration

Default constructors omit optional configuration: `socketio.NewServer()`,
`engineio.NewServer()` and `client.New(addr)`. Each role exposes its own `Option`
functions. Options apply in order; the last setting wins. Reusing options creates
independent instance configuration. Client headers/query and engine cookie/built-in
transport settings retain their construction-time copies. Callback state and custom
transports remain application-owned.

Engine.IO heartbeat and Socket.IO drain timeouts are independent.
Nonpositive queue/drain values select 64 packets and one minute. Each option's
godoc describes its defaults and bounds.
Root `WithLogger` configures Socket.IO and its engine. A later
`WithEngineOptions(engineio.WithLogger(other))` overrides only the engine's sink.

```go
server := socketio.NewServer(
    socketio.WithEngineOptions(
        engineio.WithPingInterval(25*time.Second),
        engineio.WithPingTimeout(20*time.Second),
    ),
    socketio.WithWriteBufferSize(64),
    socketio.WithCloseTimeout(time.Minute),
)
server.OnConnect("/", func(c socketio.Conn) error {
    c.Join("lobby")
    return nil
})

cl, err := client.New("http://127.0.0.1:8000",
    client.WithWriteBufferSize(64),
    client.WithCloseTimeout(time.Minute),
)
if err != nil {
    return err
}
cl.OnConnect(func(c client.Conn) error { return nil })
```

`engineio.Conn.Close` is orderly; `engineio.Abort` is immediate. `Server.Remove`
is a registry operation and does not close its transport. Configure server hooks before accepting
connections, and retain request metadata in `ConnInitor` when needed.

## Adapters and Redis

`redis.New()` returns a factory without connecting to Redis.
Namespace registration applies the factory once and retains construction errors.
It connects to Redis synchronously and can block up to `WithSubscribeTimeout`
(ten seconds by default), including subscription acknowledgements. A factory
constructs one namespace at a time, so a queued registration can wait longer.
`Server.Serve` checks for these errors when it starts. Later namespace failures do
not stop a running `Serve`: that namespace rejects connections and its emitter
returns the factory error. Register required namespaces before starting `Serve`
to detect their construction failures at startup.
`SetAdapter` affects future namespaces; existing ones keep their adapter. Nil selects
memory. Constructor options are ordered, with the last `WithAdapter` winning.
Shutdown uses optional `io.Closer` and joins completed adapter close errors with the
engine error. Adapters that own resources should implement it.
Adapters may implement `adapter.SocketLookupBinder` to receive the server's live
socket lookup independently of room membership. `Send` and `SendAll` wrap `SendTo`
and return no error, so an adapter logs their `SendTo` failures instead of dropping
them, as the Redis adapter does at WARN, or at DEBUG once closed. `Rooms(nil)` is
equivalent to `AllRooms`. The `Adapter` method set is fixed for v1; further
capabilities use optional interfaces.

```go
import (
    socketio "github.com/sshaplygin/go-socket.io"
    "github.com/sshaplygin/go-socket.io/adapter"
    redisadapter "github.com/sshaplygin/go-socket.io/adapter/redis"
)

server := socketio.NewServer(socketio.WithAdapter(redisadapter.New(
    redisadapter.WithAddr("127.0.0.1:6379"),
    redisadapter.WithPrefix("socket.io"),
)))
server.OnConnect("/", func(c socketio.Conn) error { c.Join("lobby"); return nil })
server.ForEach("/", "lobby", func(c adapter.Socket) { c.Emit("news", "hello") })
```

External adapters take `adapter.Socket`, whose methods are `ID`, `Emit` and
`EmitWithOptions`. The last method applies only `Volatile` and `NoCompress` to that
socket; the adapter owns room/exclusion/cluster selection. Root `Conn` implements this
contract. `ForEach` callbacks needing server-specific metadata can use a checked type assertion
to `socketio.Conn`. `adapter.Memory` releases its index lock before invoking sockets or
callbacks. Redis composes Memory and uses the Node-compatible wire described in
[the protocol notes](PROTOCOL.md#redis-cluster-interoperability).

`SendTo` supports exclusion and room-union deduplication across instances,
transmits volatile/compression flags, and returns encoding/publication failures.
Broadcast `PUBLISH` is bounded by `WithRequestsTimeout` (five seconds by default)
for each I/O phase (dial, write, read), so a stalled publication can take two to
three times that before `SendTo` returns the timeout error. Local delivery and
publication are not transactional: local delivery is not rolled back, and a timeout
does not mean remote instances missed the broadcast, so retrying may duplicate it.
A broadcast with a trailing callback is rejected before any delivery.
`BroadcastToRoom` and `BroadcastToNamespace` return no error: these rejections and
publication failures are logged at WARN, or at DEBUG once the adapter is closed,
one record per failed call; no rate limiting. Their result reports whether the
namespace is registered and its adapter was constructed, even after `Server.Close`,
and does not confirm delivery. Factory construction waits for subscription
acknowledgements; reconnect restores subscriptions, but missed broadcasts are not
replayed.

For errors and cancellation, assert the adapter to `redis.Cluster` and use its
context-aware methods. `IDsContext`, `AllRoomsContext` and `LenContext` query the
cluster; `ClientRooms`, `RemoteJoin`, `RemoteLeave` and `RemoteDisconnect` control
remote sockets. `CustomRequest` exchanges JSON with the handler set by
`WithCustomRequestHandler`. `WithRequestsTimeout` defaults to five seconds; caller
deadlines may shorten it. Query timeouts return validated partial results with
`redis.ErrRequestTimeout`; caller cancellation returns the context error, and
adapter closure returns `redis.ErrAdapterClosed`. IDs/AllRooms log errors and
return partial results; Len returns -1 on failure. `ClearContext` removes a snapshot
of room members under one deadline, without rolling back completed removals.

The factory shares one subscriber across its namespace adapters and invokes its
custom handler once per namespace request. A bounded worker pool executes remote
callbacks outside the reader; overload or a handler error makes Node callers time
out because that wire has no error-response field. Handlers must honor cancellation.
Server-created adapters receive an independent socket lookup, so LeaveAll does not
hide a live socket from remote commands. Standalone adapter users can optionally
bind their own lookup through `adapter.SocketLookupBinder`; custom
sockets need the corresponding Join/Leave/Disconnect/Close methods for controls.

## Client limits

`client.WithMaxMessageSize(bytes)` configures received messages; the last option wins.
The low-level equivalent is `engineio/client.Dialer.MaxMessageSize`. Zero and negative
values select the 1 MiB default. See [protocol limits](PROTOCOL.md#engineio-protocol-v3)
for the transport boundaries. Custom transports can implement `SetReadLimit(int64)`;
otherwise their implementation must enforce the limit itself. Set an explicit
larger limit before connecting if the application receives larger messages.

`polling.Default` reads `http.DefaultTransport` once, when the polling package
initializes. When it is a `*http.Transport`, the default polling HTTP client owns a
clone with up to 64 idle connections per host, shared by every client that dials
through `polling.Default`; otherwise that RoundTripper is used as it is. Later
replacement or changes of `http.DefaultTransport` do not affect it. Idle
connections stay in the pool for the transport's idle timeout after clients close;
`polling.Default.Client.CloseIdleConnections()` releases them. To choose
connection-pool or HTTP limits, supply an application-owned HTTP client with
`client.WithTransports(&polling.Transport{Client: httpClient})`; when upgrades are
wanted, add a websocket transport with a handshake timeout, such as
`&websocket.Transport{HandshakeTimeout: 20 * time.Second}`, because
`websocket.Default` has none. Reuse that HTTP client across related Socket.IO
clients and close its idle connections when the application no longer needs the
pool.

## Typed events

The root package provides `NewEvent[T]` and `NewAckEvent[T, R]`. Declare a
single descriptor and use it with both the server and the independent Go client:

```go
type Notice struct {
    ID int64
    Content string
    File parser.Buffer
}

notice := socketio.NewEvent[Notice]("notice")
if err := notice.Handle(server.Of("/chat"),
    func(ctx context.Context, conn socketio.Conn, value Notice) error {
        // ctx lasts until this namespace generation ends.
        return nil
    }); err != nil {
    return err
}
if err := notice.HandleClient(cl.Socket("/chat"),
    func(ctx context.Context, peer socketio.Endpoint, value Notice) error {
        return nil
    }); err != nil {
    return err
}
if err := notice.EmitTo(ctx, server.Of("/chat").To("room"), value); err != nil {
    return err
}
```

The snippet uses imports `context`, root `socketio` and
`github.com/sshaplygin/go-socket.io/parser`. `server`, `cl`, `ctx` and `value`
are application-owned instances. `HandleClient`
accepts either a `*client.Client` for its selected namespace or a `*client.Socket`.
Its endpoint is the actual client connection of that namespace generation.
The server callback continues to receive the exact server `socketio.Conn` role.
Typed client programs import the root package for descriptors; the client
runtime itself does not import the root socketio package. The exported
`RegisterEvent`, `SendEvent` and `RequestAck` methods of `client.Client` and
`client.Socket` are bridges for `socketio.Event` and `socketio.AckEvent`, not
application extension points.

`T` is exactly one positional argument, even when it is a slice or struct. Nested
`parser.Buffer` fields use binary attachments. Declared integer types retain their
full precision in Go-to-Go traffic. A JavaScript application remains subject to
JavaScript's numeric precision.

For a result, register and send with an acknowledged descriptor (also importing
`fmt` and `time`):

```go
lookup := socketio.NewAckEvent[int64, Notice]("lookup")
if err := lookup.Handle(server.Of("/chat"),
    func(ctx context.Context, conn socketio.Conn, id int64) (Notice, error) {
        return Notice{ID: id}, nil
    }); err != nil {
    return err
}
wait, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
result, err := lookup.EmitWithAck(wait, cl.Socket("/chat"), 42)
if err != nil {
    return err
}
fmt.Println(result.ID)
```

The ACK convention is `[null, result]` for success and
`[{"code":"...","message":"..."}]` for failure. Ordinary handler errors become
`handler_error`; recovered panics become `handler_panic`. Return
`*socketio.RemoteError` to choose a code and message, and use `errors.As` to inspect
one received from a peer. Raw or JavaScript handlers exchanging typed ACKs must
implement that envelope. Malformed responses return `ErrInvalidAck`.

A wait ends on caller cancellation/deadline, namespace disconnect
(`ErrSocketClosed`), or the internal 30-second limit (`ErrAckTimeout`). The limit
includes pre-connect buffering. Canceled buffered requests do not later flush;
admitted requests belong to one generation and are never replayed on reconnect.
Stable client sockets can buffer new requests during recovery. Typed sends on a
retained client Conn return `ErrSocketClosed` after its namespace generation ends.

Incoming handler contexts are canceled before disconnect callbacks and are
independent of application `Conn.Context()` storage and the handshake request.
Incoming event handlers share one dispatcher. Start `EmitWithAck` waits outside
a callback on that same connection, for example in a goroutine; blocking that callback
also blocks receipt of its ACK.

Typed registration rejects an existing typed or reflected listener with
`ErrDuplicateEvent`. `OnEvent` replaces the registration, and `Off`
removes either form. Empty names and reserved lifecycle names return
`ErrInvalidEventName`. Typed sends support the built-in server connections,
clients and client namespace sockets. Their `SendEvent` and `RequestAck` methods
are internal descriptor bridges, not an extension API; applications use `Event`
and `AckEvent`. An independently implemented endpoint with only `Emit` returns
`ErrUnsupportedEndpoint`. Successful sends mean local admission, and broadcasts
retain adapter error and partial-delivery behavior; they do not count
remote delivery or support broadcast ACKs.

## Migrating from googollee/go-socket.io

The fork's first release is **v1.5.0**. Its version sequence is independent of
upstream: it contains the upstream v1.7.0 history and replaces that implementation
under a new module path, with the API and behavior changes below. It is not a
compatible minor upgrade of upstream v1.4.2 or v1.7.0. The inherited fork tags
v0.9.1–v1.4.2 declare the upstream module path and must not be used as fork
versions. The [Go version floor](../README.md#install) is stated in the README.

Change imports from `github.com/googollee/go-socket.io` to
`github.com/sshaplygin/go-socket.io`, including subpackages. For v1.4.2 applications,
replace the separate `github.com/googollee/go-engine.io` dependency with this
module's `engineio` packages. A `replace` directive alone is not a drop-in
migration: package paths, type identities, constructors and interfaces changed.
Use server `socketio.Conn` in server callbacks and `client.Conn` for the new Go
Socket.IO client; the roles are independent.

After rewriting imports, `go build ./... && go vet ./...` reports the renamed,
removed and re-typed identifiers in the tables below; fix them and repeat until both
pass. Nothing under
[changed defaults](#changed-defaults-and-behavior) or
[calls that compile but change meaning](#calls-that-compile-but-change-meaning)
causes a compile error. For those, search the code for `BroadcastToRoom(`,
`Encode(`, comparisons of `.ID()` values, `OnDisconnect` reason strings,
`DefaultIDGenerator{`, `RequestChecker`, CORS middleware in front of the handler and
`err == io.EOF`, and run the application's integration tests against the new build.

Custom `socketio.Conn` implementations must add `EngineConn`, `Handshake`,
`Request` and the embedded adapter socket capability `EmitWithOptions`. The
embedded `Namespace` interface adds `Broadcast`, `Compress`, `Connected`,
`Disconnect`, `Send`, `To`, `Use` and `Volatile`; `Join` now accepts variadic room
names. `Server` and `parser.Decoder` are no longer comparable structs. Use their
pointer types when storing them as map keys or comparing instance identity.

The old `engineio/frame`, `engineio/packet`, `engineio/payload`,
`engineio/session` and `engineio/transport/utils` packages have no forwarding
imports. `engineio.Conn` is a public interface; custom implementations must add
`ReadyState`, `Transport` and `Upgraded` and use `engineio/parser.FrameType` in
reader/writer signatures. The public frame, payload and ID-generator interfaces can
be implemented without importing internal packages. For `Conn.EngineConn`, see
[connections and namespaces](#connections-and-namespaces); for typed descriptors
and client bridge methods, see [typed events](#typed-events).

Custom adapters keep the v1 `adapter.Adapter` method set and gain optional
interfaces; the contract and the Redis broadcast rules are under
[adapters and Redis](#adapters-and-redis). Prefer namespace emitters
(`server.Of(namespace).To(room).Emit`), which return broadcast errors; see
[adapter startup and errors](#adapters-and-redis).

### Changed defaults and behavior

These old values are from upstream v1.7.0 and, where marked, v1.4.2 with
go-engine.io v1.4.1. Pass Engine.IO options through `socketio.WithEngineOptions`.

| --- | --- | --- | --- |
| Cross-origin access | Polling served requests without CORS headers; websocket enforced same-origin | Every origin accepted; polling reflects Origin with credentials and overwrites the CORS origin headers set by middleware in front of the handler | `engineio.WithCORS(false)`; see [cross-origin access](#cross-origin-access). |

| Session cookie | None | Polling sets `io`, `Path=/`, `HttpOnly`, `SameSite=Strict` | `engineio.WithCookieEnabled(false)` disables it; `WithCookie` customizes attributes. Websocket-first handshakes set no cookie. |
| Engine.IO session IDs | A counter in base 36 (`DefaultIDGenerator` in v1.7.0) | Random URL-safe IDs | `engineio.WithSessionIDGenerator` supplies a custom generator. `DefaultIDGenerator.ID` still compiles but is unused. |
| Compression | Disabled | Polling gzip/deflate from 1,024 encoded bytes; websocket permessage-deflate remains off | `engineio.WithHTTPCompression(false)` disables polling compression; `WithCompressionThreshold` changes the threshold; `WithPerMessageDeflate` opts into websocket compression. |
| Ping interval / timeout | 20 s / 60 s | 25 s / 20 s | `engineio.WithPingInterval` / `WithPingTimeout` set explicit values. Nonpositive values select defaults. |
| Server idle deadline | PingTimeout alone (60 s by default) | PingInterval + PingTimeout (45 s by default) | Budget both values: restoring the old advertised 20 s / 60 s yields an 80 s server idle window. JavaScript clients and the upstream v1.7.0 Go dialer already used the sum, so their default window changes from 80 s to 45 s; the go-engine.io v1.4.1 Go dialer used PingTimeout alone. |
| Incoming server message limit | No configured limit | 1,000,000 bytes per polling POST or websocket message, after websocket inflation | Set a larger positive `engineio.WithMaxHTTPBufferSize`; there is no unlimited setting. |
| Outbound queue | `Emit` blocked until the connection's writer took the packet | `Emit` queues up to 64 packets; on overflow the packet and every later one are dropped, `ErrWriteBufferFull` is reported to `OnError`, and the connection is closed | `socketio.WithWriteBufferSize` sets the bound; see `ErrWriteBufferFull`. |
| Connect rejection | An `OnConnect` error closed the connection; v1.4.2 ignored the error and accepted the namespace | An `OnConnect` or middleware error sends an ERROR packet (type 4) and keeps the transport open, as the JavaScript reference does | Call `c.Close()` to drop the client. |
| Disconnect reasons | Every whole-connection close reported `client namespace disconnect`; namespace DISCONNECT used its packet argument, usually empty. v1.4.2 called `OnDisconnect` only for DISCONNECT packets | `OnDisconnect` runs on every close, with specific causes such as `server namespace disconnect`, `transport close`, `ping timeout`, `transport error`, `forced close`, or `client namespace disconnect` | Update reason handling; there is no legacy-reason mode. |
| Logging | v1.7.0 wrote a few messages with `log.Println`; v1.4.2 and go-engine.io logged nothing | `log/slog` WARN and DEBUG records through `slog.Default()`, so WARN records reach the standard logger | Each role's `WithLogger` sets the sink; `SOCKETIO_LOG_LEVEL` (`error`, `warn`, `info`, `debug`, `trace`) sets the library level. See the `logger` package documentation. |
| JSONP | Supported by polling | Unsupported | Use XHR polling or websocket; see [JSONP](PROTOCOL.md#jsonp). |

The new Go client has its own incoming message limit; see
[client limits](#client-limits). The [protocol rules](PROTOCOL.md) describe
transport boundaries and remaining differences.

### Calls that compile but change meaning

- Namespace socket IDs now differ: `/` uses the Engine.IO ID, while `/chat` uses
  `/chat#<engine ID>`. Use the namespace socket ID for room exclusions and remote
  adapter operations. Do not assume different namespaces share an ID.
- A v1.4.2 call `BroadcastToRoom(room, event, s)` with a string `s` is now interpreted
  as `(namespace, room, event)`. Arguments shift position and can target the wrong
  namespace or room. Supply the namespace explicitly or use
  `server.Of(namespace).To(room).Emit(event, s)`.
- With a v1.4.2-style `parser.Encoder.Encode(h, args)`, an untyped nil or nil
  `[]interface{}` now supplies a JSON `null` payload. For a namespace DISCONNECT,
  v1.4.2 wrote `1/a`; `Encode(h, nil)` now writes `1/a,null` followed by a newline.
  Use `Encode(h)` when no payload is intended: it writes `1/a,`, because the encoder
  always writes the separator after a non-root namespace, as the JavaScript
  reference encoder does. Socket.IO decoders read `1/a,` and `1/a` as the same
  packet. Non-nil argument slices remain a single JSON array; expanding them with
  `...` would instead encode only the first element.
- `engineio.Conn` readers and writers of a closed session return a wrapped
  `*engineio.CloseError` instead of a bare `io.EOF`. It unwraps to `io.EOF` only for
  a transport close. Replace `err == io.EOF` with `errors.As` for the close reason,
  or `errors.Is(err, io.EOF)` where only a transport close is meant.
- Upstream v1.7.0 ignored some `RedisAdapterOptions`: `DB` was dropped before
  dialing, so database 0 was used, and `Host`/`Port` were never applied because the
  default `Addr` is non-empty. Mapping those fields to `WithDB` or `WithAddr` can
  change the Redis database or host actually used; pass the values the old
  deployment really connected to.
- `engineio.DefaultIDGenerator{ID: n}` compiles but seeds nothing; IDs are random.
- `Server.Serve` returns nil after `Close`; upstream returned `io.EOF`.

### Upgrading Redis clusters

Redis fleets need a separate migration step: the fork's channel names and
MessagePack broadcasts are incompatible with upstream Go peers. Give the new
fleet a distinct `redisadapter.WithPrefix`, or stop all old instances before
starting the new fleet. Read the [Redis upgrade procedure](PROTOCOL.md#upgrading-from-upstream-go-redis-adapters)
before sharing a Redis service; incompatible non-root broadcasts can stop an
upstream peer's dispatcher.
